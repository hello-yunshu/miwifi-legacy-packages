# Finder probe capture — 2026-11-10
# Purpose: identify why macOS Finder (⌘K) failed against the WebDAV endpoint.
# Method: temporarily added mod_accesslog + accesslog.filename to the device config,
#         attempted a Finder connect from the user's Mac, read the log, then reverted
#         the config from the repo copy and deleted the access log. The accesslog
#         module is NOT part of the final production config.
# Endpoint at capture time: http://192.168.3.2:5005/ with Digest auth (pre-fix state)

## Raw access log lines for the Finder attempt
192.168.3.176 192.168.3.2:5005 - [10/Nov/2026:16:35:11 +0800] "OPTIONS / HTTP/1.1" 401 164 "-" "WebDAVLib/1.3"

## Observations
# 1. Finder sends exactly one request: OPTIONS / , with User-Agent WebDAVLib/1.3.
# 2. The server answers 401 with a Digest challenge (WWW-Authenticate: Digest ...).
# 3. No follow-up request appears in the log — Finder does not retry and gives up,
#    which surfaces to the user as a failed mount / 403-style error in the UI.
# 4. No PROPFIND or GET from Finder at all, so the 403 was not the first visible symptom
#    at the HTTP layer for Finder; the browser case (GET / 403) is a separate cause.

## Conclusion
# macOS WebDAVLib 1.3 supports Basic only. Digest auth makes Finder abandon the mount.
# Fix: switch auth.backend to "plain" with conf/users.basic and method => "basic".
# Root-dir listing 403 (browser) fix: load mod_dirlisting and enable dir-listing.
# Post-fix verification: ./client-fix-matrix.txt
