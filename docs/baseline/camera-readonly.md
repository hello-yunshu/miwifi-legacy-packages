# 摄像机只读行为表

只记录已恢复的创建路径与配置来源；其余文件操作仍是待确认。证据编号见 [evidence.md](evidence.md)。

## 实现形态

| 项目 | 记录 | 等级 |
| --- | --- | --- |
| 模块形态 | 只读逻辑注册在 `samba_multicall` 内，不是可原样复制的独立 `.so` | 现场、反汇编 |
| 注册入口 | `0x2275e4`，向 VFS 注册函数传入接口版本 30 | 反汇编 |
| 接口版本 | Samba 4.0.21 为 30；4.18.0 为 48 | 上游源码，本轮复核 |
| 与上游同名模块 | 上游 `vfs_readonly` 只在连接级设置只读；厂商实现增加了按时间窗拦截创建 | 上游源码、反汇编 |

旧 VFS ABI 的函数表不能直接嫁接到新版 Samba；S4 必须按目标版本接口重写，不能靠打开同名模块恢复语义。

## 创建路径行为

| 项目 | 记录 | 等级 |
| --- | --- | --- |
| 触发点 | 文件创建路径在 `0x2274a8` 附近取当前时间、解析区间两端并比较 | 反汇编 |
| 区间内 | 返回 `0xc0000022`（STATUS_ACCESS_DENIED），日志为 `create file failed caused by readonly timerange limit.` | 反汇编、二进制字符串 |
| 区间外 | 继续调用下一级创建文件路径（`0x22749c` 附近） | 反汇编 |
| 配置来源 | init 为摄像机分享加载厂商只读 VFS，并按 `misc.smb_ctl` 写入时间范围 | 现场 |
| 默认区间 | today `06:00:00` 到 tomorrow `02:00:00` | 现场 |
| 跨午夜 | 默认区间从当天 06:00 到次日 02:00，按设计跨越午夜 | 现场记录，边界未实测 |
| 参数语法与单位 | 未恢复 | 待确认 |
| 时间来源与时区 | 未恢复；系统时间变更的影响未测试 | 待确认 |

默认区间表示一个约 20 小时的写入窗口。区间外是否对所有创建都放行、区间内是否也拦截打开/覆盖，目前只从创建路径得出，不能外推到其他操作。

## 文件操作覆盖

| 操作 | 是否受该时间窗约束 | 等级 |
| --- | --- | --- |
| 创建文件 | 是（区间内拒绝） | 反汇编 |
| 打开已有文件 | 未确认 | 待确认 |
| 覆盖 / 追加 / 截断 | 未确认 | 待确认 |
| 重命名 / 删除 | 未确认 | 待确认 |
| 长时间保持的句柄跨过区间端点 | 未确认 | 待确认 |
