# SMB 软件包详细开发计划

计划基线：2026-11-07。目标是在 R2D 官方固件上运行持续维护的 Samba，解决 Emby 访问问题，并保留经验证的小米授权、摄像机和管理功能。完成定义是功能、权限、实机和恢复共同达标；仅编译成功不足以发布。

## 当前事实与待确认事项

| 内容 | 状态 | 含义 |
| --- | --- | --- |
| 目标固件及平台 | R2D、ROM 2.25.209、ARMv7、uClibc 0.9.33.2、Linux 2.6.36 | 首个支持组合，其他型号不在首版承诺范围 |
| 原厂 Samba | 4.0.21，存在小米定制 | 已支持 SMB 3.0，问题不能归结为只支持 SMB1 |
| Emby 认证故障 | 已定位访客映射后 SPNEGO mechListMIC 失败 | 隔离对照支持该因果链，不能用关闭 MIC 作为产品修复 |
| 官方 SDK | GCC 4.8.2/uClibc 工具链已验证 | 不代表能直接构建所有新软件或兼容全部旧内核调用 |
| Samba 4.23.13 实验 | 构建、QEMU 原厂 libc、Emby 目录和账户、SMB3.1.1 加密读取通过 | 使用 Ubuntu 宿主内核，未验证实机性能或完整播放 |
| 下一版目标 | 先前核实为 4.25.1；构建前重新核实 | 尚未编译或验证 |
| MAC 权限 | 已恢复核心分支，有离线模型 | 完整调用路径、MAC 解析和所有失败分支仍需确认 |
| 相机 readonly | 发现创建文件的时间限制定制 | 未恢复完整参数与边界语义 |
| 管理链路 | shareUpdate、配置、热插拔及插件生命周期存在联动 | 新版消息和进程控制兼容尚未验证 |

上表“已验证”来源于本次研究实验，不表示公共仓库已有完整可重建证据。S0 要完成证据索引和可公开摘要。

## S0：现场基线与行为合同

**任务**

- 只读记录固件、架构、内核、实际可用内存、磁盘文件系统、原厂程序与库散列、运行版本和进程参数。没有包数据库时用 ELF 与进程证据补足。
- 建立 smbd/nmbd/smbpasswd 的 multicall 关系、配置来源、PID/锁/状态目录、监听地址、启动及重载调用图。
- 梳理 MAC 两个列表的写入者、格式、生命周期、IP 到 MAC 的查找方式，以及列表缺失、未知 MAC、跨网段和 IPv6 行为。
- 记录摄像机 readonly 的配置键、参数单位、时间来源、打开与创建语义。把反汇编结论与推测分开。
- 收集公开可复现的合成配置，列出 macOS、Emby、小米 WiFi、摄像机等可用测试设备。当前用户有 Mac，暂无 Windows 11 设备；记录 macOS 系统版本及可用测试工具。保存基线备份与校验，不上传真实共享清单或设备身份。

**交付**：脱敏设备清单、管理调用图、权限真值表、摄像机行为表、证据索引和未知项清单。

**验收**：每项结论标注现场观察、隔离测试、源码/反汇编或待确认。缺设备和无法观测的功能必须留在支持限制里。

## S1：最新稳定版的干净构建

**依赖**：S0 的平台基线；厂商语义研究可以继续进行。

**任务**

- 重新核实上游最新稳定版，锁定源码散列并验证签名；对编译器、Python、依赖和内核要求做差异检查。
- 把现有 4.23.13 适配逐个迁移，先判断新版本是否仍需要；禁止盲目套用补丁或把认证失败改为成功。
- 旧 GCC TLS、泛型、缺失 reflink、有限 spawn 适配与构建期 QEMU 执行分别记录。明确 spawn 支持范围和使用调用点，升级出现新调用必须重新审计。
- 将私有库、安装目录和运行启动器集中配置，消除偶然依赖宿主 lib64、研究目录、临时缓存或构建树的情况。
- 从全新源码和干净输出目录构建，记录 ELF 解释器、动态库依赖、大小、启用功能与未启用的编译加固。

**交付**：版本锁定清单、补丁序列、容器构建入口、干净构建报告；产物状态为 lab。

**验收**：不依赖前次构建残留即可成功；目标程序可报告版本，testparm 成功，动态库依赖全部有来源。不能把 hash 下载验证称作已验证上游签名。

## S2：隔离环境的完整 SMB 回归

**依赖**：S1。使用合成账户、临时目录和回环地址；不修改生产媒体库。

| 测试组 | 主要用例 | 通过条件 |
| --- | --- | --- |
| 认证 | 访客、正确账户、错误密码、禁用账户、私有共享拒绝访客 | 允许与拒绝均有明确状态；没有认证绕过 |
| 协议 | SMB2/SMB3 支持矩阵，SMB1 禁用 | 与声明一致，客户端协商证据可追溯 |
| 保护 | 账户强制签名、强制加密、拒绝不满足策略的客户端 | 验证强制策略，不能只证明客户端“可选择”加密 |
| 文件 | 中文、特殊字符、大文件、随机定位读、只读拒写、受控可写共享 | 内容校验一致；拒绝路径没有落盘副作用 |
| Emby | 目录、存在检查、实际媒体读取、拖动定位、完整播放 | 无 DLL 或认证代理修改；访问和实际播放分别记录 |
| macOS（首轮必测） | Finder 挂载、账户访问、中文文件、读取/写入策略、重连和安全弹出；记录系统版本及实际协商信息 | 通过原生 SMB 客户端验证，并用可用诊断工具记录协议、签名和加密状态；挂载成功本身不证明加密已启用 |
| Windows 11（待补测） | 有设备后记录版本和策略，以账户测试签名/加密及访客限制 | 当前不阻塞首轮验收，发布说明明确未验证，不声明 Windows 11 兼容 |
| 会话 | 并发、断线重连、错误请求、服务重启 | 无挂死、持续资源泄漏或权限串用 |

**交付**：自动化实验脚本、协议与文件校验摘要、客户端版本矩阵、清理验证。

**验收**：正向与拒绝测试均通过；没有完整播放设备时只声明目录与读取通过。QEMU 结果不提升为实机支持。首轮客户端覆盖 macOS 与 Emby；Windows 11 保留为待补测项，不阻塞该范围内的候选发布。macOS 或 smbclient 的成功不作为 Windows 11 策略兼容证据。

## S3：小米 MAC 策略适配

**依赖**：S0 明确行为，S1 提供目标 API，S2 提供安全回归基础。

- 核对已恢复的核心规则：两个列表任意命中时选择非 browseable 共享，否则选择 browseable 共享。继续恢复 IPC$、连接级检查及普通 Samba 权限检查顺序。
- 明确共享枚举、直接访问、重连和缓存会话四类入口，不能只在目录显示层做限制。
- 比较在 Samba 内部窄接口补丁和 VFS/外部策略接口上的实现能力；完成覆盖表后再选。VFS connect 能力不足以证明枚举权限正确。
- MAC 获取与授权读取单独封装；测试 ARP/邻居缺失、MAC 改变、IP 复用、跨网段、IPv6、文件更新及解析失败。不能把不可解析的客户端意外授予整盘访问。
- 权限撤销对已连接会话的行为要与原厂对照并明确记录。无法复现原厂安全行为时，应说明差异并阻止候选发布，不静默改变规则。

**交付**：接口决策记录、完整真值表、最小实现补丁、跨枚举与连接的负向集成测试。

**验收**：授权、拒绝和撤销行为均覆盖；未知地址/身份路径无提权；离线模型通过不等于本阶段完成。MAC 本身可伪造，其兼容适配不应被宣传为强身份认证。

## S4：摄像机 readonly 适配

**依赖**：S0 恢复参数与边界，S1 的新版 VFS API；可与 S3 独立开发。

- 从原厂行为明确时间区间、跨午夜、端点、时区/系统时间变更、配置缺失及畸形参数的处理。
- 用新版 VFS 接口实现已确认的行为，核对 create/open、覆盖、追加、截断、重命名、删除与长连接是否受原厂规则约束；不凭模块名称假设都被限制。
- 准备模拟请求回归；有真实摄像机后测试实际写入和回放。旧 VFS ABI 的二进制模块不直接加载。

**交付**：独立模块或补丁、参数说明、边界测试、与原厂的行为差异。

**验收**：核心时间和文件行为与确认合同一致；未进行真实摄像机测试时，摄像机兼容保持未验证。若用户不使用摄像机，可另行定义明确标注的受限包，不能默认为完整替代。

## S5：小米管理与服务生命周期

**依赖**：S3、S4 的功能边界已明确；先在实验环境运行。

- 梳理 shareUpdate、UCI/模板、supervisord、插件状态及磁盘/USB 热插拔调用；建立新版测试配置生成器或适配层。
- 对命令行、进程名、PID/锁路径、退出码、smbcontrol reload、重启和配置检查逐项验证。不要假设新版 smbcontrol 可控制旧版进程或反向兼容。
- 新版验证通过后才采纳配置；配置生成失败保留上次有效配置并输出可诊断错误。原厂与新版不得同时写同一 TDB、锁、PID 或运行目录。
- 测试小米 WiFi 中共享启停、权限修改、磁盘连接/断开，以及 MiniDLNA/电视通知等共用链路的副作用。

**交付**：启动与配置适配器、生命周期矩阵、配置失败和恢复测试。

**验收**：所有声明支持的管理操作生效，失败可恢复；没有真实 App 或外围设备验证时对应功能继续标为未验证。

## S6：真实路由器的受控实验

**依赖**：S2 通过，S0 已有恢复基线。优先备用同型号设备；在生产设备运行候选前给出具体试验范围、文件清单与恢复步骤，遵守用户关于不贸然修改的要求。

- 首次仅部署到独立测试目录，验证程序启动、私有库、旧内核调用、随机源、文件锁、线程/进程和持久存储行为。
- 确认实际绑定和隔离方式后再启动服务；默认端口被占用时先做本地测试。不能假设 Emby 支持非标准 SMB 端口。
- 用合成文件测试读写与恢复，再进行真实客户端验证。持续观察 CPU、内存、I/O、连接数、日志增长、网络和管理界面响应。
- 对签名、加密、并发读取分别测量吞吐与路由负载，阈值根据原厂基线和设备余量制定，记录测试时间和负载，避免虚构通用性能指标。

**交付**：实机内核兼容报告、性能与资源对照、失败诊断；状态为 device-test。

**验收**：没有影响联网或管理功能的不可接受回退，资源留有基线定义的余量。缺失关键旧内核功能时暂停该产物路线，评估兼容实现或独立运行环境；不以关闭安全保护掩盖失败。

## S7：切换与回滚演练

**依赖**：S3—S6 的目标功能通过；具体部署切换需提供可审阅方案，再按用户授权执行。

- 设计版本目录、状态目录与配置备份，明确哪些数据可迁移、哪些不可与旧 Samba 共用。备份本身需实际验证可恢复。
- 先停原服务、确认端口释放，再启新服务并健康检查；失败则恢复原服务和配置。避免双实例争用同一磁盘权限或状态库。
- 安装、升级、重复执行、卸载、回滚、启动失败、配置损坏、重启和磁盘暂时缺失分别演练。
- 原厂固件升级可能覆盖适配路径，须定义检测与恢复方式，不静默强行接管。

**交付**：安装/升级/卸载与恢复工具、操作清单、故障演练记录。

**验收**：回滚后原厂共享、权限和小米管理恢复，实际核对数据和文件完整性。未演练恢复不得形成正式安装包。

## S8：候选发布与后续升级

**依赖**：上述目标功能通过，限制公开且无关键未解决阻断。

- 发布清单附版本、依赖、散列、构建环境、补丁、许可证、对应源码、客户端与设备矩阵、资源测试和已知限制。
- 提供签名、验证方式和升级/恢复说明；测试凭据、设备信息、SDK/固件与未知授权材料不进入公开包。
- 在干净环境复建后发布 release-candidate；经过限定设备组合的实机验证再声明 supported。
- 上游新版本迁移重复 S1/S2；认证、策略、VFS、管理或内核变化触发相应 S3—S7 回归。维护版本支持状态，不能一次构建后长期无更新。

## 决策与阻断记录

| 阻断 | 要做的判断 | 不可省略的证据 |
| --- | --- | --- |
| 新版不支持旧编译环境 | 小范围兼容补丁还是升级工具链 | 失败日志、运行 ABI、内核调用测试 |
| MAC 入口无法完整覆盖 | 内部补丁还是重新划分适配边界 | 枚举/直连/会话撤权的覆盖矩阵 |
| 摄像机语义未知 | 继续逆向或明确缩小首版支持范围 | 行为差异与使用者可见的支持限制 |
| 资源不足 | 功能裁剪或迁移服务位置 | 同负载基线，且安全策略保持有效 |
| SDK/依赖再分发不明 | 本地自备还是仅发布合法材料 | 文件级许可证和对应源码核查 |

当前可执行的首项工作是 S0 的证据整理与 S1 的最新稳定版干净构建。以上为开发计划，未创建自动部署、监控或定时任务。
